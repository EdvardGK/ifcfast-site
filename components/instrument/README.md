# `<Instrument />`

A cross-filtering read of one federated slice of a building: a graphite
panel of cells that all describe the same product set, where selecting
in any cell filters every other cell and the 3D viewport.

It is deliberately **self-contained**. It imports nothing from the app
it lives in — no design tokens, no Tailwind, no data helpers — so it can
be copied into another project as a folder. Its only peer dependencies
are `react` and `three`.

## Use

```tsx
import { Instrument } from "@/components/instrument";
import data from "@/public/receipts/model/instrument.json";

<Instrument data={data} initialModel="Architectural" />;
```

### Props

| prop | type | meaning |
|---|---|---|
| `data` | `InstrumentData` | The whole slice. See the contract below. Required. |
| `initialModel` | `string?` | Discipline loaded on first tap. Defaults to `data.models[0].name`. |

The component is a Client Component (`"use client"`). It holds all
filter state internally and emits nothing; if a host needs the current
selection, add a callback prop rather than reaching into it.

## Data contract — `instrument.json`

Generated by ifcfast (`scripts/generate_receipts.py`). Every number the
panel prints comes from this file; the GLBs supply geometry only.

```jsonc
{
  "generated": "2026-09-07",
  "ifcfast_version": "0.4.42",
  "scope": "First Floor, all five disciplines",
  "poster": "/receipts/model/clinic-floor1.webp",

  // one GLB per discipline, so they load lazily and toggle independently
  "models": [
    { "name": "Architectural",
      "glb": "/receipts/model/clinic-floor1-architectural.glb",
      "products": 812, "bytes": 1500000 }
  ],

  "storeys":   [{ "guid": "…", "name": "First Floor", "elevation_m": 3.8, "products": 11784 }],
  "classes":   [{ "entity": "IfcWallStandardCase", "model": "Architectural", "n": 312, "volume_m3": 410.2 }],
  "materials": [{ "name": "Gypsum Wall Board", "n": 120 }],

  // one row per product in the GLBs, keyed by IFC GlobalId
  "products": {
    "<guid>": {
      "entity": "IfcWallStandardCase",
      "model": "Architectural",       // must match a models[].name
      "storey": "First Floor",        // must match a storeys[].name
      "volume_m3": 1.23,
      "volume_reliable": true,        // false ⇒ volume_m3 is a prism fallback
      "material": "Gypsum Wall Board",
      "clash_partners": ["<guid>"]    // guids in this same map
    }
  }
}
```

Joins the component relies on:

- `products[*].model` → `models[*].name`
- `products[*].storey` → `storeys[*].name`
- `products[*].material` → `materials[*].name`
- `products[*].clash_partners[*]` → keys of `products`
- **`products` keys → the glTF node `extras.guid` in that discipline's GLB**

That last one is the whole selection mechanism.

## GLB requirements

Written by `m.to_gltf()`, which stamps each product node's glTF
`extras` with `guid` and `entity`. three.js exposes glTF `extras` as
`Object3D.userData`, and the viewport walks up from a hit mesh until it
finds a node carrying `userData.guid`.

**Selection never keys on material names.** ifcfast does not guarantee
one material per product (parser GH #146), so a material-name scheme
silently mis-selects. If a GLB has no `extras.guid`, taps on it will
find nothing and the panel simply never selects — that is the intended
failure, not a crash.

Budget: the disciplines load one at a time on request, and a model over
5 MB is labelled `heavy` in its chip.

## Behaviour worth knowing

- **Poster first.** No WebGL context, no `three` chunk, and no network
  request until the reader taps *Load the model*.
- **Missing GLBs are a state.** Each file is `HEAD`-probed before it is
  handed to `GLTFLoader`, so an unpublished model shows *Model pending*
  instead of looping console errors. Every other cell keeps working.
- **Tap vs orbit.** `pointerdown` records position and time;
  `pointerup` selects only if the pointer moved < 6 px in < 400 ms.
  Anything else was an orbit. A tap on empty space clears the selection.
- **Touch.** The canvas wrapper is `touch-action: pan-y` until the
  reader activates the viewer, so a vertical swipe over the poster
  scrolls the page rather than fighting it. After activation
  OrbitControls takes the gestures.
- **Static camera.** No autorotate, no fly-in. The camera moves only
  when a person moves it, or when the visible set changes and the view
  is re-framed.
- **No horizontal overflow.** Every cell is `min-width: 0`, every long
  string ellipses, and long registers scroll inside their own cell.

## Layout

Phone: one column, in DOM order — title, quantities, viewport,
selection, storeys, classes, materials, products. Desktop (≥ 64rem):
a four-column grid,

```
title  title  quant  quant
storey view   dist   reg
storey sel    mat    reg
```

with a bounded height, so the device reads as an instrument set into the
page rather than a section that grows without limit.

## Theming

All colour lives in the `.instrument` block at the top of
`instrument.module.css` as custom properties (`--ink`, `--sheet`,
`--fg`, `--acc`, …). Override them on a wrapper to reskin it. Fonts
come from `--font-plex-sans` / `--font-plex-mono` if the host defines
them, and fall back to system faces otherwise.
