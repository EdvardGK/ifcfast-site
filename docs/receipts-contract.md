# ifcfast.com receipts — data contract

The landing page makes no hand-typed numbers. Every figure is read at
build time from `public/receipts/*.json`, generated by
`scripts/generate_receipts.py` in the parser repo against the
buildingSMART **Medical-Dental Clinic** sample (CC BY 4.0, five
discipline models: Architectural, Structural, HVAC, Plumbing,
Electrical). Every file carries `generated` (ISO date), `ifcfast_version`,
and `machine` so staleness is visible.

Principle: one claim per section, the number that proves it, the
command that reproduces it.

### `receipts/model/`
- `clinic-floor1.glb` — the one 3D asset on the page. First Floor of
  every discipline, `m.subset()` per model → `to_gltf(cut_openings=True)`,
  quantized + instanced. **Hard budget 3 MB.** Loaded only on tap/click.
- `clinic-floor1.webp` — static still used as the poster and as the
  desktop hero image.
- `clinic-floor1.index.json` — `{guid: {entity, model, storey, volume_m3, volume_reliable, clash_partners: [guid…]}}` for every product in the GLB; drives the selection receipt panel.
- `ATTRIBUTION.md` — CC BY 4.0 credit.

## The instrument (owner decision, 2026-09-06)
The federation + clash section's 3D block is not a plain viewer: it is
**the instrument** — the graphite cross-filtering panel from
`app/mockups/ab/page.tsx` chapter 06 (`InstrumentChapter`, cells:
title block, quantities readout, storey bars, viewport, class
distribution, material register, product register), which the owner
picked, rebuilt ground-up for this page:
- Phone-first: the cells stack in one column in a fixed order
  (viewport → storey → distribution → register), each full-width; on
  desktop they form the grid. No cell may overflow the viewport width.
- Cross-filter both ways: tapping a storey bar / class row / register
  row highlights the matching products in the model and filters the
  other cells; tapping a product in the model selects it and shows its
  receipt (guid, class, discipline, storey, volume + reliability,
  material, clash partners) and dims the rest.
- Data: `receipts/model/instrument.json` (below) + the discipline GLBs.
- Dark panel (graphite, one accent) embedded in the light receipt page —
  it is a device, the page is the paper.
- Self-contained: lives in `components/instrument/` with its own data
  types and no imports from the rest of the site, so the same component
  can be lifted into another app (sprucelab model view is the intended
  second home). Document its props + data contract in a README there.

## Selection (owner requirement)
Tapping a product in the model cross-filters the page: a receipt panel
(stacked below the viewer on phone) shows guid, class, discipline,
storey, volume + reliability, clash partners; the rest of the model
dims. Selection keys on the glTF per-product node `extras.guid` /
`extras.entity` (written by `to_gltf`), never on material names.

## Rules for the page
- Phone-first: single column at every width; nothing wider than the
  viewport; no `<pre>` that can scroll the page — snippets wrap.
- No 3D behind text. The GLB is a block below its section text, poster
  first, loads on interaction, never autoplays a camera.
- No component from the old page or the mockups is reused.
- Every number rendered comes from these files; the version badge comes
  from PyPI at request time and `generated` is shown next to the receipts.
